# 8. Feature Plan & Four-Layer Categorization

本文件定義 ItemTrace V3 的功能架構清單、演進變更分類與嚴格的四層分級架構。

---

## 1. 功能四層分級架構（The 4-Layer Hierarchy）

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. Core Experience (核心體驗 - 所有人每天必用)                          │
│    • 手機隨手拍照記錄 (Mobile Capture)                                  │
│    • AI 主動理解與自動整理 (AI Drafter & Organizer)                     │
│    • 超低摩擦確認 (1-Tap Save / Inline Quick Edit)                      │
│    • 紀錄圖文檢視與大圖縮放 (Record View)                               │
│    • 全域即時模糊搜尋 (支援品名、型號、特徵與半截序號)                  │
│    • 隨手追加照片與生活筆記 (Follow-up Additions)                       │
├────────────────────────────────────────────────────────────────────────┤
│ 2. Supporting Experience (支援體驗 - 讓生活更便利)                     │
│    • 生活備忘維護 (購買日期/來源、保固到期日、存放位置)                 │
│    • 狀態管理 (在手上 / 已離手 / 作廢)                                 │
│    • 手機與桌機跨端無縫切換 (QR Code 直連)                              │
│    • 基礎分類標籤快速篩選                                              │
├────────────────────────────────────────────────────────────────────────┤
│ 3. Advanced Capability (進階能力 - 特殊情境/特定時刻召喚)              │
│    • 標籤貼紙列印與 QR Code 實體綁定                                   │
│    • 外觀快照與雙視窗並排比對 (Compare)                                 │
│    • 一鍵匯出完整紀錄封存包 (Record Package ZIP)                        │
│    • 相機大批照片時間智慧切分匯入 (/unsorted)                          │
├────────────────────────────────────────────────────────────────────────┤
│ 4. Infrastructure (底層資產 - 默默守護，無感知)                       │
│    • 原始照片不可覆寫與 SHA-256 去重                                   │
│    • Events 變更完整歷史與單欄位精確復原 (Revert)                      │
│    • SQLite WAL 安全本機備份與完整性檢查 (Backup & Verify)             │
│    • 開放 API 契約與開源自足資料夾結構                                │
└────────────────────────────────────────────────────────────────────────┘
```

---

## 2. 功能演進分類（Evolution Decisions）

* **KEEP（保留不動的後端資產）**：
  - `original/` 原始照片目錄與不可覆寫原則。
  - `ITM-0001` 短碼 ID 生成體系。
  - 序號大寫去空白正規化與 409 撞號警告。
  - `events` 表的變更追蹤與單欄位還原機制。
  - Chromium + GDI 本地標籤機列印管線。
  - SQLite WAL 本機備份機制。
* **CHANGE（重新設計以適應現代生活）**：
  - **記錄流程**：由「先傳入 Inbox → 手動分組 → 再建檔」改為「隨手連拍 → AI 理解整理 → 一鍵存起來」。
  - **AI 互動**：由「手動點按鈕 → 逐欄點接受」改為「拍完預設生成整理結果 → 看一眼整體存起來」。
  - **紀錄呈現**：由生硬的庫存資料表改為以大圖為主、規格清爽、支援生活備忘的生活化檢視。
  - **進階功能收攏**：列印標籤、外觀比對、封存包匯出全部收攏至卡片右上角的 `⋯` 選單，平時不干擾首頁。
* **REMOVE（移除的生硬負擔）**：
  - 常駐導覽的 Inbox 選單。
  - 繁重的物品庫存管理概念與資料庫表格心智。
  - 物品 Draft 狀態。
  - 一級導覽的標籤範本管理。
  - 前端基準展示頁 `/design`。
* **ADD（新增的生活化能力）**：
  - 拍照記錄全螢幕連拍托盤。
  - 彈性相片理解（結構化物品整理 vs 生活隨拍相片留存）。
  - 序號旁快速查看標籤照片特寫的放大鏡按鈕。
  - 存放位置（Location）與保固到期日（Warranty）具名屬性。
  - 手機連線專屬 QR Code 引導卡片。

## 3. 明確拒絕的想法紀錄（Rejected Ideas）

| 被拒絕的想法 | 表面吸引力 | 拒絕理由（為什麼不該做） |
|---|---|---|
| **全套 ERP / 複雜進銷存系統** | 可以管進貨成本與利潤 | 偏離個人日常生活工具定位；讓資料模型與介面極端複雜化。 |
| **雲端多人帳號與登入機制** | 多人可以一起登入編輯 | 摧毀 local-first 本機資料主權原則；大幅增加伺服器依賴與運維成本。 |
| **強迫使用者逐欄打勾確認** | 確保每一欄都親手點過 | 使用體驗極為煩躁，扼殺隨手拍照留存的輕鬆感；改用「主管驗收，點擊局部微調」。 |
| **鑑識與二手拍賣專用詞彙全面侵入** | 強調賣家防調包與證據 | 把普通生活使用者嚇退；相關能力歸入進階選單與底層資產，介面保持中性親切。 |
| **自動過期刪除舊資料** | 節省硬碟容量 | 違反原始紀錄神聖原則；幾年前拍下的東西往往在最意外的時刻拯救主人。 |
