# 7. AI Experience: "AI Fills, Human Confirms"

本文件定義 ItemTrace V3 的 AI 核心體驗。整個互動哲學由過去繁雜的「逐欄審核」革新為極致低摩擦的 **「AI 主動幫我整理，我只需看一眼確認」**。

---

## 1. 核心哲學：主管審閱模式（Supervisor Review Mode）

過去很多工具把 AI 輔助做得很反人性：
* 要使用者手動點擊「呼叫 AI」；
* AI 產生建議後，跳出 5 個確認框，要求使用者每個欄位逐一打勾；
* 如果序號錯一個字母，使用者只能按「拒絕」，然後自己從頭手打 16 碼。

在 ItemTrace V3 中，AI 的體驗就像一位訓練有素的高級秘書：
1. **主動理解與整理（Proactive）**：拍照結束時，AI 自動在背景通讀照片，理解內容並梳理出整齊的資料。
2. **完整呈現結果（Presented as Whole Draft）**：使用者看到的是一份已經整理好的卡片預覽。
3. **整體驗收（1-Tap Save）**：大部分情況下，AI 辨識都很準確，使用者瞄一眼「都對」，按一下 **「✓ 存起來」** 即可留存。
4. **局部微調（Inline Quick Edit）**：如果發現型號少了一個字，直接在該文字上點一下即可編輯，不需要對其他欄位進行繁瑣操作。

```text
┌────────────────────────────────────────────────────────┐
│                   AI 整理的結果預覽                     │
├────────────────────────────────────────────────────────┤
│ [照片預覽區: 外觀、背板、規格標籤 (3張)]                 │
│                                                        │
│ 品名: ASUS ROG STRIX B650E-F GAMING WIFI               │
│ 品牌: ASUS           型號: B650E-F                      │
│ 類別: 電腦零件 / 主機板                                │
│ 序號: 6LWMF1234567   [🔍 對照標籤貼紙照片]             │
│ 狀況: 外觀九成新，無氧化，原裝彩盒配件完整             │
├────────────────────────────────────────────────────────┤
│  [ ✓ 存起來 ]               [ ✎ 局部微調 ]             │
└────────────────────────────────────────────────────────┘
```

## 2. 智慧提煉策略與彈性理解（Extraction & Adaptive Understanding）

當多模態 Vision 模型接收到多張照片時，後端提示詞（Prompt）引導其依循現實生活慣例進行智慧解構：

### 2.1 實體物品與裝備（Structured Item Extraction）
若照片中包含具體的硬體、器材、工具、商品或 3C 產品：
* **品名 (`name`)**：提煉最自然、最完整的人類生活稱呼（例如「SONY A7M4 全片幅單眼相機」）。
* **品牌 (`brand`)**：提取主製造商（例如「SONY」）。
* **型號 (`model`)**：提取製造商原廠內部型號（例如「ILCE-7M4」）。
* **類別 (`category`)**：自動分類至生活化層級（例如「攝影器材 / 相機」）。
* **序號 (`identifier:serial`)**：
  - 專注尋找機身或外盒上的 `S/N`、`Serial No.`、`序號` 標籤。
  - 嚴格逐字照抄，不自行腦補格式。
  - 記錄該序號是從第幾張照片中讀出的（`source_photo_index`）。
* **狀況 (`condition`)**：根據外觀有無刮痕、標籤有無破損、有無外盒給出客觀敘述。

### 2.2 生活隨拍與非特定物品（Adaptive Photo Understanding）
若使用者拍下的是風景、寵物、朋友、隨手便籤或無法規格化的物件：
* AI 不會硬套「品牌」「型號」「序號」等生硬欄位。
* AI 自動總結出生活化標題與描述，作為富含上下文的相片紀錄保存。
* 使用者永遠不需要在拍照前「選擇分類」或「選擇模式」，隨手一拍即可。

## 3. 序號精確度與對齊檢驗（Serial OCR with Visual Context）

序號是實體物品最重要的身分證明，也是 AI 最容易把 `O` 與 `0`、`I` 與 `1` 搞混的地方。
我們既要保證可信度，又不能打斷極速流程：

1. **標籤對照縮圖**：
   - 在結果中的序號文字旁邊，放置一個小放大鏡與來源標籤縮圖。
   - 點擊放大鏡，即刻在畫面上彈出標籤特寫照片，使用者可以一眼核對字元。
2. **點選即改（Quick Edit）**：
   - 若發現把 `0` 讀成 `O`，點擊文字彈出鍵盤，游標直接聚焦在該字元，修改後直接按下確認。
3. **撞號偵測（Conflict Warning）**：
   - 若後端發現其他紀錄已存在同序號，以醒目黃色標註：「⚠️ 另一筆紀錄（ITM-0012）也有相同序號，請確認是否為同一件」。

## 4. 錯誤處理與自動降級（Graceful Fallbacks）

* **未設定 AI 金鑰（No API Key）**：
  - 拍完照片後，草稿呈現基本空欄位，溫和提示：「未設置 AI 金鑰，可手動填寫或至設定中配置（選用）」。依然可以一鍵儲存只有照片的紀錄。
* **網路逾時或服務商 5xx 故障（Network / Provider Error）**：
  - 不跳全螢幕阻斷視窗。卡片提示：「AI 暫時無法連線，可先存下照片，日後隨時點擊重新辨識」。
* **API Key 安全保證**：
  - 任何送給使用者的錯誤訊息均經過後端正則脫敏（Redaction），密鑰絕不外流。

## 5. 多模型適配（Model Compatibility）

延續 `shop/ai_client.py` 的標準 OpenAI 相容協定：
* **Google Gemini 官方直連（首選推薦）**：`gemini-2.5-flash`（OCR 精準、反應極快、繁體中文理解力優秀）。
* **OpenRouter 彈性路由**：支援 OpenRouter 上所有多模態視覺模型。
* **自訂相容端點 (Custom)**：支援本地 vLLM、Ollama 等自架模型。
