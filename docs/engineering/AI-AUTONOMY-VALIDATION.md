## 2. 描述契約評估（§3）

**現況**：9 個錄製情境＋本次 live 中，`attribute:description` 出現次數 **0**。模型傾向用 `name`＋`category`＋`attribute:color` 表達「這是什麼」；對不可辨識物件誠實留白。

**問題**：
1. 沒有「描述」這一層，生活隨拍（產品願景 P5、AI-EXPERIENCE §2.2）只有單一 `name` 可承載，長一點的敘述會擠進名字、反而影響檢索語義。
2. 名字成為事實後（自動填入）承擔檢索錨點；描述性名字（「馬克杯」）可以接受，但沒有地方記錄「看見的 vs 推測的」。

**建議的最小 prompt/契約調整（本階段不實作）**：在 PROMPT 增加一條規則，例如：
> 即使認不出品牌或型號，只要照片看得到東西，就用看得見的描述當 `name`（例如「紅色馬克杯」），並用 `attribute:description` 寫 1–2 句：先寫「看見的」，推測處用「看起來像……」標示。不要為了湊欄位編造品牌、型號或用途。

**為什麼是最小**：不改 schema、不改契約驗證、不改政策（description 已是可自動套用的描述性屬性）；只是把既有的 `attribute:description` 慣例真的用起來。**驗收（下一階段）**：C1 型情境的期望改為「必須出現 description（或等價的敘述欄位）且不含編造的品牌/型號」，並以 harness 重跑 L1–L6b＋C1 回歸。

**限制**：合成圖比真實照片容易；description 品質（語氣、長度）需以真實照片另評，不在本階段。

## 4. Undo 與來源語義（§4）

### 已驗證的語義比較

| 動作 | 現行語義 | 判定 |
|---|---|---|
| 使用者輸入/確認值 | 事件 actor=user → 永久受保護（自動永不覆蓋；新證據只能進確認清單） | ✓ 保留 |
| 使用者修正 AI 判讀 | 同上（修正即 user 事件） | ✓ 保留 |
| 使用者復原一次自動套用 | 還原前值＋建議 rejected＋寫回 actor=user → 之後**不再自動**（含空值不回填） | ✓ 保留（見下） |
| 之後有重大新證據 | 仍會分析、仍會提出 → 進確認清單（不自動） | ✓ 不會被「永久鎖定」擋住再詮釋——只是需人確認 |

### 建議的最簡規則（下一階段實作）

1. **復原＝永久停止對該欄位的「自動」套用，但不阻止分析與確認**——維持現行，這已是保護意圖與允許再詮釋的最小交集。
2. **修補過期復原（實測缺陷）**：本階段重現——使用者 PATCH `brand=我已自行確認的品牌` 後，對較舊的自動套用按復原（API 回 200），**brand 被靜默清空**，使用者輸入消失。
   驗收：`undo` 必須驗證「目前值仍等於該次自動套用的值」；否則回 409＋說明（不是靜默覆寫）。同時涵蓋「已被更新的自動值」與「使用者後續編輯」兩種過期情況。
3. **搜尋一致性**：修訂後舊詞仍可搜（accepted 建議值）；復原後該詞不再可搜（rejected）、還原值由欄位搜尋涵蓋——語義一致；但第 2 點的過期復原會連帶刪掉使用者可搜的值，修補後即解。

## 5. 跨證據矛盾（§5）

**現行規則可靠處理的**（✓ 實測/回放）：
- 同一輪輸出的同欄位不同值 → `external_conflict`（S1b 的雙序號即為真實案例）。
- 購買資訊與身分來自不同照片 → `external_conflict`（L4 回放、C4b 注入、S3 的背帶收據——三種內容都正確）。
- 使用者鎖定值 vs 新提案 → 確認清單。

**需要更好模型輸出（建議以 prompt 處理，不做品牌硬規則）**：
- 兩張身分照片並存時，模型可能**沉默擇一**（S1b 的 brand 直接以 SONY 修訂 BOSE，另一個序號才因重複值被攔到）。建議 prompt 增句：「不同照片支持不同身分時，請分別輸出各自的建議（或標示不確定），不要只挑一個。」——讓既有重複值偵測能把身分衝突也升級。驗收：新 harness 情境 C6（兩張不同品牌標籤）→ brand 衝突進確認而非靜默修訂。

**需要更多證據選擇**：無新需求（見 §3）。

**本階段無法可靠解決（明確承認）**：收據是否真的屬於這件物品，目前僅靠「同張照片是否提供身分」的啟發式；更深層語義（配件、代買、多物品合照）維持保守升級，不擴充品牌特例規則。

## 6. 剩餘重大失敗模式（彙總）

1. **過期 undo 覆寫後續編輯**（已重現；最高優先修補）。
2. 模型對跨照片身分沉默擇一（S1b；需 prompt 調整＋C6 驗證）。
3. `attribute:description` 從未被使用（需 prompt 調整＋C1 驗收）。
4. 中段照片身分遺失（低頻；維持現狀）。
5. 收據歸屬判斷僅啟發式（設計上接受；由衝突清單兜底）。
