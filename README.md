# ItemTrace — 拍下來，AI 幫你記住，以後找得到

完整的手機優先 MVP（最小可用產品），用 AI 和照片把日常物品紀錄下來。

**核心流程**：隨手拍 📷 → AI 自動整理 ✨ → 一鍵存起來 ✓ → 日後快速找回 🔍

## 產品特色

- **手機優先設計**：在手機上拍照、整理、搜尋；電腦作為伺服器
- **零打字直接存**：拍幾張照片，AI 自動辨識名稱、品牌、型號、序號，建議都對就一鍵存檔
- **AI 可靠辨識**：基於使用者驗收，不自動蓋掉人工修改；失敗時照片保留，可原地重試
- **紀錄持續完善**：已存的物品可追加新照片、AI 重新理解；支援編輯名稱、品牌、狀況備忘
- **秒級尋回**：搜尋名稱、品牌、型號、序號任意一部分，即時顯示匹配的物品
- **垃圾桶與還原**：不要的紀錄先「移至垃圾桶」從列表與搜尋隱藏，照片與資料保留、可一鍵還原；要徹底清除再按「永久刪除」
- **本地優先與隱私**：紀錄、資料庫與原始照片儲存在自己的電腦；沒有內建雲端同步。若啟用外部 AI，選取的照片與相關紀錄上下文會送往所設定的 AI 服務分析（詳見下方「安全與隱私」）
- **雙語支援**：繁體中文和英文，輕按切換
- **打標籤與列印**：為物品列印 QR 碼標籤，方便掃描回查

## 需要什麼

- **Windows / macOS / Linux** 系統運行伺服器
- **Python 3.11 以上**
- **任何手機或平板**（同一個 Wi-Fi）
- **可選 AI**：Google Gemini、OpenRouter 或自訂 OpenAI 相容 API

## 快速開始

### 1. 安裝依賴

```bash
pip install -r requirements.txt
```

### 2. 初始化

```bash
python shopctl.py init       # 建立 config.json 與 catalog.db
```

### 3. 啟動服務

```bash
python serve.py              # http://127.0.0.1:8731/
```

Windows 用戶可以直接雙擊 **`啟動 ItemTrace.bat`**。

### 4. 在電腦上試試

打開瀏覽器：**<http://127.0.0.1:8731/>**

### 5. 從手機連進來（免設定檔）

在電腦上打開 **設定 → 手機配對**，點選 **「開始配對」**，畫面會出現 QR Code。

用手機（同一個 Wi-Fi）掃描 QR Code，瀏覽器會自動完成配對並開啟 ItemTrace。
不需要手動修改 `config.json`、不需要查詢電腦 IP，配對一次後即可持續使用
（服務重啟也還在）。要停用某支手機，回到同一頁的「已配對的裝置」按
**撤銷配對**即可。

> **既有安裝升級**：舊版 `config.json` 裡的 `server_host: "127.0.0.1"`
> （舊預設值）會自動改用區網綁定，升級後不需要手動修改就能手機配對。
> 如果刻意只想給這台電腦使用，把 `local_only` 設為 `true`；此時配對按鈕
> 會明確說明如何解除純本機模式。

> **安全模型**：服務預設綁定 `0.0.0.0`（區網），但授權分三層 ——
> 只有**電腦本機（loopback）**與**已配對裝置**能存取資料、照片與設定；
> 區網上其他未配對的裝置只會看到配對說明頁，拿不到任何資料。
> 配對碼 5 分鐘過期、只能使用一次，且裝置權杖存在伺服器端的雜湊裡
> （配對碼放在 QR 網址的 `#` fragment，不會出現在 HTTP 存取日誌）。
> 仍請只在家用等受信任網路使用，不要把連接埠轉發到公開網路。
>
> **照片與資料傳輸提醒**：ItemTrace 的資料庫、紀錄與原始照片預設保存在執行伺服器的電腦。若設定並使用外部 AI 服務，ItemTrace 伺服器會將本次選取的照片，以及供模型理解紀錄所需的文字／既有紀錄上下文，傳送至你設定的服務端點；這不是只在本機完成的分析。供應商的接收、記錄與保留方式依該服務的政策及設定而定。未設定 AI 時，仍可手動建立與搜尋紀錄，不會呼叫 AI 服務。

## 使用流程

### 📷 拍照記錄

1. 點擊 **「📷 開始拍照記錄」** 按鈕
2. 拍多張照片（正面、規格標籤、銘牌、配件均可）
3. AI 自動分析這些照片，提示：
   - ✓ **看見**：高置信度的結果（如果清楚地看到序號）
   - ~ **推測**：低置信度的結果（如果是猜測的）
4. 檢查 AI 的建議是否正確；可修改任何欄位
5. 點擊 **「✓ 存起來」** —— 完成！

### 🏠 首頁與搜尋

- **最新紀錄**：保存後立即顯示在首頁頂部，並短暫高亮
- **搜尋任何部分**：搜尋名稱、品牌、型號、序號末碼，都能快速找到
- **詳細資訊卡片**：點擊任何物品查看完整詳情

### 📝 編輯與追加

在物品詳情頁：

- **編輯欄位**：修改名稱、品牌、型號、分類、外觀狀況等
- **📷 加入照片**：為既有物品追加新照片
- **✨ AI 重新整理**：當追加新照片時，AI 在既有資訊的基礎上重新理解
- **複製序號**：一鍵複製序號到剪貼簿

### 🔍 搜尋與尋回

- 在首頁搜尋框輸入任何關鍵字
- 支援模糊搜尋（部分品牌、型號、序號末位）
- 即時篩選結果，點擊進入詳情

### 🗑 垃圾桶與刪除

- **移至垃圾桶**：在物品詳情頁點 **「移至垃圾桶」**。紀錄會從首頁與搜尋
  結果隱藏，但照片與資料暫時保留 —— 隨時可以還原。
- **還原**：首頁右上角 🗑 進入垃圾桶，點 **「還原」**。紀錄重新出現在列表
  與搜尋，並回到移入前的狀態（原本「已離手」的還原後仍是「已離手」）。
- **永久刪除**：在垃圾桶頁點 **「永久刪除」** 並再次確認。紀錄、照片與
  所有關聯資料都會從資料庫與檔案中移除，**無法復原**。

> **注意**：永久刪除**不會**自動清除先前建立的備份快照（`backups/`）中的
> 副本；有執行過 `shopctl.py backup` 的話，那些快照仍保有刪除前的資料。
> ItemTrace 也不會自動定期清除垃圾桶 —— 只有你按下「永久刪除」才會清。

### 🏷️ 列印標籤（選用）

- 在物品頁點擊 **「列印」** 按鈕
- 選擇標籤範本、印表機
- 看預覽後一鍵列印 QR 碼標籤
- 掃碼回查物品詳情

## 架構

```
手機 / 電腦瀏覽器
    ↓ 本機或區網連線
ItemTrace 伺服器 (FastAPI)
    ├── SQLite 資料庫 (catalog.db)
    ├── 原始照片儲存 (files/ 目錄)
    ├── AI 分析（選用；由伺服器呼叫設定的 Gemini / OpenRouter / 自訂端點）
    │      └── 啟用時會把照片與必要上下文送至該外部服務
    ├── 列印管線 (Chromium + GDI)
    └── 搜尋 & 檢索
```

**特色**：
- 零建置前端（純 HTML/CSS/JavaScript，無框架）
- 不需要 Node.js／npm 前端建置工具；Python 後端依 `requirements.txt` 安裝套件
- 原始照片永不覆寫；新拍照自動編號
- 紀錄與原始照片本機保存；無內建雲端同步（外部 AI 傳輸例外，詳見隱私說明）

## 配置說明

`config.json` 可配置項：

| 欄位 | 預設 | 說明 |
|---|---|---|
| `data_root` | `.` | 資料根目錄 |
| `database` | `catalog.db` | 資料庫檔案名稱 |
| `backup_dir` | `backups` | 備份資料夾 |
| `backup_keep` | `30` | 保留備份數量 |
| `server_host` | `0.0.0.0` | 綁定位址。舊版設定檔裡的 `127.0.0.1`（舊預設值）會自動改用 `0.0.0.0`，升級後不需手動編輯 |
| `local_only` | `false` | 純本機模式：只綁 `127.0.0.1`，手機無法連線（其餘安全防護不變） |
| `allowed_hosts` | `[]` | Host 白名單的補充項（自訂主機名；loopback 與本機介面位址一律允許） |
| `server_port` | `8731` | 連接埠 |
| `max_request_bytes` | `33554432` | 單一請求大小上限（32 MB） |
| `max_upload_bytes` | `25165824` | 單一上傳檔案上限（24 MB） |
| `max_upload_files` | `20` | 一次上傳最多檔數 |
| `max_image_pixels` | `50000000` | 單張圖片像素上限（50 MP） |
| `analyze_per_minute` | `10` | 每分鐘 AI 呼叫上限 |
| `enable_docs` | `false` | 是否啟用 API 文件 (`/docs`) |

## AI 配置（選用）

1. 進入 **<http://127.0.0.1:8731/settings>**
2. 選擇 AI Provider：
   - **Google Gemini**（免費 tier 可用，推薦）
   - **OpenRouter**（支援多種模型）
   - **自訂 OpenAI 相容 API**
3. 輸入 API key 並測試連線
4. 回到物品頁點 **「✨ AI 重新整理」** 就能使用

> API key 儲存在執行 ItemTrace 的電腦上的 `tools/ai_config.local.json`（已排除於版本控制），伺服器不會把 key 回傳給手機瀏覽器。使用 AI 時，伺服器會用該 key 向你設定的供應商驗證，並傳送本次分析需要的照片與文字上下文；因此，**使用外部 AI 就代表這些分析輸入會離開本機**。不同供應商的資料記錄／保留政策可能不同，請依自己的隱私需求選擇服務。AI 設定的存取仍受既有授權規則保護：未配對的區網裝置不能修改設定。

## 語言支援

UI 支援繁體中文和英文，可在任何頁面右上角切換（沒有 UI 時按 ⚙️ 設定鍵）。

- **物品資料保持原文**：名稱、品牌、型號、備忘等你輸入的內容不會翻譯
- **只翻譯 UI**：按鈕、標籤、欄位名、錯誤訊息等
- **選擇記在瀏覽器**：不存進資料庫，換裝置各自記憶

## 離線工具

```bash

python shopctl.py stats

# 完整性檢查（找出資料庫有紀錄但檔案不見的照片）
```

## 常見問題

**Q：資料存在哪裡？**  
A：所有資料存在 `config.json` 指定的 `data_root` 目錄（預設當前資料夾）。
`catalog.db`（SQLite）+  `files/`（照片）+ `backups/`（快照）。
整個資料夾可隨時備份或轉移。

**Q：支援多人共享嗎？**  
A：目前設計給單一使用者。沒有帳號密碼，但區網裝置需要先在電腦「設定」
頁的「手機配對」區塊點選「開始配對」才能存取；未配對的裝置只能看到配對說明頁。
多人協作需要未來功能開發。

**Q：可以上傳多少張照片？**  
A：單個物品沒有硬性上限。單次上傳受限於 `max_upload_files`（預設 20 張）、
檔案大小上限 24 MB、圖片像素 50 MP。都可在 config.json 調整。

**Q：ItemTrace 支援 iPhone 的 HEIC／HEIF 照片嗎？**  
A：目前不支援直接匯入 HEIC／HEIF；選取時會提示格式不支援，不會把它當成成功匯入。請先從手機或電腦將照片轉存／匯出為 JPEG 或 PNG，再匯入。這是目前版本的限制，不代表原始照片被轉換或覆寫。

**Q：手機相機拍不出來怎麼辦？**  
A：可以從手機相簿匯入已存在的照片，或使用電腦的檔案選擇器／拖放。相機與相簿選擇器的實際介面依裝置和瀏覽器而異。

**Q：AI 不準怎麼辦？**  
A：直接在 review 畫面改掉。AI 失敗也能存檔（只存照片，沒有 AI 建議）。
日後可追加照片，讓 AI 重新理解。

**Q：不小心刪掉了，救得回來嗎？**  
A：移到垃圾桶的紀錄可以隨時還原（照片與資料都保留，不會自動過期清除）。
只有在垃圾桶按「永久刪除」並確認後才會真正清除，且無法復原 ——
但先前建立的備份快照（`backups/`）中的副本不會被自動清除。

**Q：可以離線使用嗎？**  
A：沒有設定 AI provider 時，可以在本機手動建立、編輯與搜尋紀錄，不需要連外 AI 服務。手機連線到電腦仍需在同一個區域網路。若啟用 Gemini、OpenRouter 或其他外部 AI，分析時需要連線至該服務。

## 安全與隱私

- **本地優先**：ItemTrace 的資料庫、紀錄與原始照片保存在執行伺服器的電腦，沒有內建雲端同步或帳號服務。
- **防禦桌面攻擊**：
  - Host 白名單（防 DNS rebinding）
  - Origin 驗證（防跨站請求）
  - 自訂標頭檢查（防簡單 CSRF）
  - 媒體附件化（防上傳 HTML 執行）
  - CSP 與 nosniff 標頭
- **資源上限**：請求、檔案、圖片像素都有上限，防止拒絕服務
- **AI 資料傳輸**：未設定 AI 時不呼叫外部模型；啟用後，伺服器會將使用者選取的照片與必要的文字／紀錄上下文傳送給設定的 AI 端點。請先確認供應商的資料使用政策與保留設定。
- **列印管線**：預設啟用沙箱，防止 PDF 惡意程式碼
